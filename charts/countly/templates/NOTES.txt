1. Release status

   Countly {{ .Chart.AppVersion }} is installed as release
   {{ .Release.Name }} in namespace {{ .Release.Namespace }}.

2. Access

{{- if .Values.ingress.enabled }}
{{- range .Values.ingress.hosts }}
   Dashboard: http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host | default "<ingress-address>" }}
{{- end }}
{{- else if .Values.gateway.enabled }}
{{- range .Values.gateway.hostnames }}
   Dashboard host: {{ . }}
{{- end }}
   Use the scheme configured by the referenced Gateway listener (HTTP or HTTPS).
{{- else }}
   kubectl -n {{ .Release.Namespace }} port-forward service/{{ include "countly.fullname" . }} 8080:{{ .Values.service.port }}
   Dashboard: http://127.0.0.1:8080
{{- end }}

3. Credentials

   Complete the initial Countly administrator setup in the dashboard.
   MongoDB credentials are read from the bundled dependency or the Secret
   configured by externalMongodb.existingSecret.

4. Health

   kubectl -n {{ .Release.Namespace }} rollout status deployment/{{ include "countly.fullname" . }}
   kubectl -n {{ .Release.Namespace }} get pods,service,endpoints

5. Persistence

   All durable Countly data is stored in MongoDB. Confirm the MongoDB PVC or
   managed database retention policy before sending production events.

6. Backup and restore

{{- if .Values.backup.enabled }}
   Backup schedule: {{ .Values.backup.schedule }}
   Target: {{ .Values.backup.s3.endpoint }}/{{ .Values.backup.s3.bucket }}/{{ .Values.backup.s3.prefix }}
   Run and verify an independent restore before relying on the schedule.
{{- else }}
   Scheduled backups are disabled. Enable backup.enabled or use the managed
   MongoDB provider's backup service, then test a restore.
{{- end }}

7. Upgrade

   Back up MongoDB, review Countly and plugin compatibility, then run:
   helm upgrade {{ .Release.Name }} helmforge/countly -n {{ .Release.Namespace }} --reuse-values
   If the release was installed directly from OCI, run instead:
   helm upgrade {{ .Release.Name }} oci://ghcr.io/helmforgedev/charts/countly -n {{ .Release.Namespace }} --reuse-values

8. Security and documentation

   Restrict networkPolicy ingress and egress for production, keep both public
   listeners behind TLS, and store credentials in Secrets.
   Documentation: https://helmforge.dev/docs/charts/countly

Happy Helmforging :)
