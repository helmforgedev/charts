Discourse has been installed as an experimental chart.

1. Installation summary
=======================
- Release: {{ .Release.Name }}
- Namespace: {{ .Release.Namespace }}
- Chart: {{ .Chart.Name }} {{ .Chart.Version }}
- Application: Discourse {{ .Chart.AppVersion }}
- Image: {{ include "discourse.image" . }}
- Support boundary: upstream classifies this container and Kubernetes path as unsupported for production.

2. Access
=========
- Service: {{ include "discourse.fullname" . }}
- Port: {{ .Values.service.port }}
- Hostname: {{ .Values.discourse.hostname }}

Run:
  kubectl port-forward --namespace {{ .Release.Namespace }} service/{{ include "discourse.fullname" . }} 8080:{{ .Values.service.port }}

Then open:
  http://{{ .Values.discourse.hostname }}:8080

3. Getting started
==================
Wait for the singleton pod:
  kubectl wait --namespace {{ .Release.Namespace }} \
    --for=condition=Ready pod \
    --selector app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/name={{ include "discourse.name" . }} \
    --timeout=15m

The first boot runs database migrations and asset precompilation and can take several minutes.

4. Credentials
==============
- The Discourse secret key base is stored in Secret {{ include "discourse.secretName" . }}.
- PostgreSQL credentials are sourced from the selected database Secret.
- SMTP is skipped by default. Configure real SMTP before inviting users.

7. Troubleshooting
==================
Inspect startup and migration logs:
  kubectl logs --namespace {{ .Release.Namespace }} deployment/{{ include "discourse.fullname" . }} --all-containers=true --tail=300

Inspect the previous container after a restart:
  kubectl logs --namespace {{ .Release.Namespace }} deployment/{{ include "discourse.fullname" . }} --previous --tail=300

Inspect events:
  kubectl get events --namespace {{ .Release.Namespace }} --sort-by=.lastTimestamp

Confirm dependencies:
  kubectl get pods,service --namespace {{ .Release.Namespace }}

Do not increase replicaCount. The experimental image performs boot-time migrations and asset preparation.
Do not disable /shared persistence. Uploads, backups, logs, and runtime state use this path.
