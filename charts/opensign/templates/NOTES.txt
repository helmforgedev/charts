Open the frontend and create the initial user through the application. Before
accepting production documents, verify HTTPS, signing, SMTP, document storage,
and a complete backup and restore test.

7. Troubleshooting
==================
Inspect pods and recent events:

  kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}
  kubectl -n {{ .Release.Namespace }} get events --sort-by=.lastTimestamp

Inspect current and previous logs:

  kubectl -n {{ .Release.Namespace }} logs deployment/{{ include "opensign.componentName" (dict "root" . "component" "backend") }}
  kubectl -n {{ .Release.Namespace }} logs deployment/{{ include "opensign.componentName" (dict "root" . "component" "backend") }} --previous
  kubectl -n {{ .Release.Namespace }} logs deployment/{{ include "opensign.componentName" (dict "root" . "component" "frontend") }}

If MongoDB authentication fails, verify the selected database mode, Secret key,
URI authSource, TLS parameters, and NetworkPolicy egress. If uploads fail,
verify the local PVC or S3 endpoint, bucket permissions, base URL, credentials,
and private egress rules. If signing fails, verify that both PFX values exist
and decode to a valid PKCS#12 certificate and passphrase.

8. Backup, upgrade, and resources
================================
Back up MongoDB, documents, the application Secret, signing certificate, and
integration credentials as one recovery set. Test restoration in an isolated
namespace before depending on it.

Before upgrading, read upstream release notes, verify both official image
digests, back up state, and expect a brief backend interruption due to Recreate.
