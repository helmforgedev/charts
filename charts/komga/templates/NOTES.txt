5. Security and exposure
========================
The Service is internal by default. Use TLS when enabling Ingress or Gateway API.
With chart defaults, the workload blocks privilege escalation and uses RuntimeDefault seccomp.
Explicit podSecurityContext or securityContext values take precedence over those defaults.
The chart always disables Kubernetes API token mounts. UID/GID and filesystem access remain
compatible with existing PVCs.
For upgrades from older releases, prefer --reset-then-reuse-values so new defaults are merged
with prior explicit values. --reuse-values alone may retain older security-context values.
Store backup credentials in an existing Secret or ExternalSecret for production.

=================================
