3. Administrator credentials
============================

The administrator username and password are stored in Secret:
  {{ include "grafana.adminSecretName" . }}

Read the username:
  kubectl get secret -n {{ .Release.Namespace }} {{ include "grafana.adminSecretName" . }} -o jsonpath="{.data.{{ .Values.admin.userKey }}}" | base64 --decode

Read the password:
  kubectl get secret -n {{ .Release.Namespace }} {{ include "grafana.adminSecretName" . }} -o jsonpath="{.data.{{ .Values.admin.passwordKey }}}" | base64 --decode

The Secret initializes the administrator only when the database is new.
For an existing database, change the password through Grafana, its API, or the
administrator CLI against the configured database, then synchronize the Secret.

5. Validate the deployment
==========================

Check rollout completion:
  kubectl rollout status -n {{ .Release.Namespace }} deployment/{{ include "grafana.fullname" . }}

Inspect pods and restart counts:
  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

Call the native health endpoint through the Service:
  kubectl run grafana-health --rm -i --restart=Never -n {{ .Release.Namespace }} --image=curlimages/curl:8.17.0 -- \
    curl --fail --silent http://{{ include "grafana.fullname" . }}:{{ .Values.service.port }}/api/health

The response should report database status "ok".

6. Provisioning and operations
==============================

Datasources, dashboard providers, dashboards, and alerting rules are rendered
from provisioning.* values. Changes update the ConfigMaps and trigger a rollout.

List chart-owned ConfigMaps:
  kubectl get configmap -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

Inspect Grafana logs:
  kubectl logs -n {{ .Release.Namespace }} deployment/{{ include "grafana.fullname" . }} --tail=200

Inspect recent events:
  kubectl get events -n {{ .Release.Namespace }} --sort-by=.lastTimestamp

{{- if .Values.persistence.enabled }}
The data claim is {{ include "grafana.claimName" . }}.
Before SQLite file-level backup, stop Grafana cleanly or use a storage snapshot
with application-consistent procedures. Back up the database, configuration,
plugins, and provisioning source values together.
{{- else }}
Warning: persistence is disabled. SQLite metadata and installed plugins are
lost when the pod is replaced. Use only for disposable environments or with an
external database and declarative provisioning.
{{- end }}

7. Troubleshooting
==================

Describe the Grafana pod:
  kubectl describe pod -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

Check the generated configuration:
  kubectl get configmap -n {{ .Release.Namespace }} {{ include "grafana.fullname" . }}-config -o yaml

Check PVC status:
  kubectl get pvc -n {{ .Release.Namespace }} {{ include "grafana.claimName" . }}

If readiness fails, inspect /api/health and database connectivity first.
If plugin startup fails, verify every plugins.preinstall entry is pinned and
that NetworkPolicy egress permits the plugin source.
If an externally exposed URL redirects incorrectly, set grafana.rootUrl and
grafana.serveFromSubPath consistently with the proxy path.
If multiple replicas fail validation, configure an external database and a
storage topology that does not share a ReadWriteOnce volume.

Recommended next steps:

  - enable ServiceMonitor and permit the monitoring namespace in NetworkPolicy
  - configure database and storage backups before production use
  - test restore and upgrade procedures in a non-production namespace
