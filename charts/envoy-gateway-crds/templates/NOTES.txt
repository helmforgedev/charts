2. Verify the CRDs
==================

List the selected CRDs:

  kubectl get crd -l gateway.networking.k8s.io/policy=direct
  kubectl get crd | grep gateway.envoyproxy.io

Verify Gateway API metadata:

  kubectl get crd gateways.gateway.networking.k8s.io \
    -o go-template='version={{`{{ index .metadata.annotations "gateway.networking.k8s.io/bundle-version" }}`}} channel={{`{{ index .metadata.annotations "gateway.networking.k8s.io/channel" }}`}}{{`{{ "\n" }}`}}'

Verify Envoy Gateway metadata:

  kubectl get crd envoyproxies.gateway.envoyproxy.io \
    -o go-template='version={{`{{ index .metadata.annotations "helmforge.dev/bundle-version" }}`}}{{`{{ "\n" }}`}}'

3. Wait for discovery
=====================

Before installing or diffing Envoy Gateway, wait for every CRD to become
Established. For the default bundle:

  helm show crds oci://ghcr.io/helmforgedev/helm/envoy-gateway-crds \
    --version {{ .Chart.Version }} > envoy-gateway-crds-installed.yaml

  kubectl wait --for=condition=Established \
    --timeout=120s \
    -f envoy-gateway-crds-installed.yaml

Confirm Kubernetes discovery:

  kubectl api-resources --api-group=gateway.networking.k8s.io
  kubectl api-resources --api-group=gateway.envoyproxy.io

4. Install Envoy Gateway
========================

Install the application only after discovery contains the required APIs:

  helm upgrade --install envoy-gateway \
    oci://ghcr.io/helmforgedev/helm/envoy-gateway \
    --namespace envoy-gateway \
    --create-namespace \
    --set crds.enabled=false

The first application diff can now retain Kubernetes validation:

  helm diff upgrade envoy-gateway \
    oci://ghcr.io/helmforgedev/helm/envoy-gateway \
    --namespace envoy-gateway \
    --allow-unreleased \
    --set crds.enabled=false

5. Upgrade CRDs
===============

Never rely on helm upgrade to update objects from crds/. Follow the documented
server-side apply procedure before upgrading the application controller.

Perform a server-side dry-run first. Do not use --force-conflicts without
auditing field ownership and the installed bundle version/channel.

CRD downgrade is unsupported. A Helm rollback of this release does not and must
not downgrade CRD schemas.

6. Uninstall behavior
=====================

Uninstalling this release preserves:

- All selected CRDs.
- Every custom resource stored through those CRDs.
- The safe-upgrade policy and binding when managed.

This is intentional protection against cluster-wide data loss. Follow the
manual removal procedure only after confirming no controller or custom resource
uses the APIs.

7. Migration warning
=====================

Existing Envoy Gateway 1.10.1 installations must first upgrade to the bridge
application release. Do not install the standalone policy over a policy owned by
the application release. Follow the UID-preserving ownership transfer in:

  https://helmforge.dev/docs/charts/envoy-gateway-crds#migration-from-1101
