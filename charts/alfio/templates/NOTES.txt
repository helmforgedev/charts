1. Summary

   alf.io {{ .Chart.AppVersion }} is deployed as release {{ .Release.Name }}
   in namespace {{ .Release.Namespace }}. The application listens on port
   {{ .Values.alfio.containerPort }} and the Service exposes port {{ .Values.service.port }}.

2. Access

{{- if .Values.ingress.enabled }}
{{- range $host := .Values.ingress.hosts }}
   Web application: http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}/
   Administration:  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}/admin/
{{- end }}
{{- else }}
   Start a local port-forward:

     kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "alfio.fullname" . }} 8080:{{ .Values.service.port }}

   Open http://localhost:8080/.
{{- end }}

3. Getting Started

   Wait for the server, open the application, and complete the first-time setup:

     kubectl wait --for=condition=ready pod -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=server -n {{ .Release.Namespace }} --timeout=300s

4. Credentials

   The chart does not create alf.io administrator credentials. The initial
   setup flow creates the administrator. Database credentials come from the
   chart-managed Secret or database.external.existingSecret.

5. Configuration

   Image:                     {{ include "alfio.image" . }}
   Additional profiles:       {{ .Values.alfio.profiles }}
   Public base URL:           {{ default "not configured" .Values.alfio.baseUrl }}
   ServiceAccount token:      {{ .Values.serviceAccount.automountServiceAccountToken }}
   Ingress NetworkPolicy:     {{ .Values.networkPolicy.enabled }}
{{- if .Values.postgresql.enabled }}
   Database:                  bundled PostgreSQL at {{ include "alfio.dbHost" . }}:{{ include "alfio.dbPort" . }}
{{- else }}
   Database:                  external PostgreSQL at {{ include "alfio.dbHost" . }}:{{ include "alfio.dbPort" . }}
{{- end }}

6. Validation

     kubectl get deployment,service,pod -l app.kubernetes.io/instance={{ .Release.Name }} -n {{ .Release.Namespace }}
     kubectl get networkpolicy -l app.kubernetes.io/instance={{ .Release.Name }} -n {{ .Release.Namespace }}
     kubectl get --raw /api/v1/namespaces/{{ .Release.Namespace }}/services/http:{{ include "alfio.fullname" . }}:http/proxy/healthz

7. Troubleshooting

     kubectl describe pod -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=server -n {{ .Release.Namespace }}
     kubectl logs deployment/{{ include "alfio.fullname" . }} -n {{ .Release.Namespace }} --all-containers --tail=200
     kubectl get endpointslices -l kubernetes.io/service-name={{ include "alfio.fullname" . }} -n {{ .Release.Namespace }}
     kubectl get events -n {{ .Release.Namespace }} --sort-by=.lastTimestamp

   If startup is blocked, check PostgreSQL reachability and credentials. If a
   custom listener fails, verify SERVER_PORT and the named HTTP container port.
