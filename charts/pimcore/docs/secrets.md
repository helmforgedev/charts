# Secrets

The application Secret contains:

- `application-secret`
- `admin-password`
- `product-key`
- `instance-identifier`
- `encryption-secret`
- `mercure-jwt-key`

Only `product-key`, `instance-identifier`, and `encryption-secret` must remain
identical for deployments that represent the same registered Pimcore instance.
The application secret, administrator password, and Mercure JWT key are
environment-specific unless an operator deliberately shares the full Secret.

Generated application, administrator, and Mercure values are retained through
Helm upgrades. Registration values are never generated by the chart because
Pimcore validates their cryptographic relationship.

Use `auth.existingSecret` or External Secrets in production. Database, queue,
and cache password Secrets are referenced separately. Password-bearing DSNs are
assembled only inside containers.

Rotate application, administrator, Mercure, database, and broker credentials
with coordinated workload rollouts. Changing `encryption-secret` can make
existing encrypted data unreadable and requires a planned decrypt/re-encrypt
migration. Product re-registration, product-key generation, and
instance-identifier changes are separate registration operations; keep the
three registration values as one matching set.
