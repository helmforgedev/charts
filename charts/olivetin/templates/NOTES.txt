3. Getting started
==================

1. Wait for the OliveTin pod:

   kubectl wait --for=condition=Ready pod -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/name={{ include "olivetin.name" . }} --timeout=5m

2. Port-forward the Service and open http://127.0.0.1:1337.

3. Run only the actions you have reviewed and test their least-privilege access.

4. Security
===========

OliveTin executes configured shell commands. Before exposing it:

- configure OliveTin authentication and ACLs or an authenticated reverse proxy;
- keep ServiceAccount token mounting disabled unless actions require it;
- grant only the RBAC, volumes, executables, and credentials each action needs;
- use Secrets or External Secrets for credentials, never the ConfigMap;
- restrict network access according to the destinations used by your actions.

7. Troubleshooting
==================

Inspect pods, init containers, logs, and events:

  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -o wide
  kubectl describe pod -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/name={{ include "olivetin.name" . }}
  kubectl logs deploy/{{ include "olivetin.fullname" . }} -n {{ .Release.Namespace }} --all-containers --tail=200
  kubectl get events -n {{ .Release.Namespace }} --sort-by=.lastTimestamp

Common checks:

- If config rendering fails, validate values.config as YAML and review tpl usage.
- If the UI is unavailable, verify PORT, Service endpoints, and edge routing.
- If actions fail, verify command paths, credentials, mounts, RBAC, and egress.
- If metrics fail, verify metrics.enabled, the metrics port, and ServiceMonitor.
- If data disappears, confirm actions write durable output to the /data mount.
