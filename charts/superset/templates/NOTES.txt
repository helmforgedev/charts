3. Administrator credentials

Administrator username: {{ .Values.superset.adminUsername }}

Read the password without printing any other Secret keys:

  kubectl get secret {{ include "superset.secretName" . }} \
    --namespace {{ .Release.Namespace }} \
    --output jsonpath='{.data.{{ .Values.superset.existingSecretPasswordKey | default "admin-password" }}}' | base64 --decode

Use an operator-managed `superset.existingSecret` in production. Preserve both
the administrator password and `SECRET_KEY` during upgrades and restores.

Back up PostgreSQL before upgrading Superset. The initialization path runs
`superset db upgrade` and `superset init` for each release revision.

7. Backup and recovery

{{- if .Values.backup.enabled }}
Scheduled PostgreSQL backup: {{ .Values.backup.schedule }}

  kubectl get cronjob {{ include "superset.fullname" . }}-backup \
    --namespace {{ .Release.Namespace }}
{{- else }}
The chart backup CronJob is disabled. Configure PostgreSQL backup and a tested

Redis is not a source of truth and is not included in PostgreSQL backups.

8. Security and next steps

Review the effective contract and NetworkPolicy before exposing Superset:

  helm get values {{ .Release.Name }} --namespace {{ .Release.Namespace }} --all
  kubectl get networkpolicy {{ include "superset.fullname" . }} \
    --namespace {{ .Release.Namespace }} --output yaml

Build an immutable image with required database drivers and set
`superset.installPythonPackages=false` for production.
