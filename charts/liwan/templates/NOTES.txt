4. Persistence and backup
=========================
{{- if .Values.persistence.enabled }}
Persistence: enabled
Data claim: {{ include "liwan.dataClaimName" . }}
Quiesce incoming writes or stop the Deployment before snapshotting /data.
{{- else }}
Persistence: disabled. Data is stored on emptyDir and is lost with the Pod.
{{- end }}
Test restore into an isolated namespace and protect copies off-cluster.

5. Availability and resources
==============================
Recreate upgrades intentionally include downtime and prevent concurrent writers.
Do not scale this Deployment or attach the claim to another running release.
Set CPU, memory, and PVC capacity for traffic volume and retention.

6. Monitoring and network
=========================
kubectl logs -n {{ .Release.Namespace }} deployment/{{ include "liwan.fullname" . }} --tail=100
Monitor restarts, public tracking requests, PVC growth, and backup age.
{{- $networkPolicy := .Values.networkPolicy | default dict }}
NetworkPolicy enabled: {{ $networkPolicy.enabled | default false }}
NetworkPolicy enforcement requires a compatible CNI. Explicitly allow the edge.

7. Upgrade and recovery
=======================
Back up /data, review upstream storage changes, and watch the Recreate rollout.
helm upgrade {{ .Release.Name }} helmforge/liwan -n {{ .Release.Namespace }} -f values.yaml
kubectl rollout status -n {{ .Release.Namespace }} deployment/{{ include "liwan.fullname" . }}
Helm rollback changes manifests and images; it does not reverse DuckDB migrations.
