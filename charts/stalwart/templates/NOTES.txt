3. Getting started
==================
Wait for the StatefulSet:

  kubectl -n {{ .Release.Namespace }} rollout status statefulset/{{ include "stalwart.fullname" . }} --timeout=5m

Stalwart 0.16 reads only its DataStore object from config.json. Configure
listeners, stores, domains, accounts, telemetry, and the Coordinator through
the Web UI or stalwart-cli.

4. Credentials
==============
This chart does not generate a default password. Supply recovery or permanent
administrator credentials through extraEnv.valueFrom, extraEnvFrom, or an
ExternalSecret. Remove recovery credentials after creating permanent access.

6. Validation commands
======================
  helm -n {{ .Release.Namespace }} status {{ .Release.Name }}
  kubectl -n {{ .Release.Namespace }} get pods,svc,pdb
  kubectl -n {{ .Release.Namespace }} wait pod -l app.kubernetes.io/instance={{ .Release.Name }} --for=condition=Ready --timeout=5m
  curl -fsS http://127.0.0.1:8080/healthz/ready
  helm -n {{ .Release.Namespace }} test {{ .Release.Name }}

The official readiness endpoint proves DataStore initialization. It does not
prove coordinator membership; validate cluster events and behavior separately.

7. Troubleshooting
==================
  kubectl -n {{ .Release.Namespace }} get pods -o wide
  kubectl -n {{ .Release.Namespace }} get events --sort-by=.lastTimestamp
  kubectl -n {{ .Release.Namespace }} describe statefulset/{{ include "stalwart.fullname" . }}
  kubectl -n {{ .Release.Namespace }} logs statefulset/{{ include "stalwart.fullname" . }} --all-containers --tail=200
  kubectl -n {{ .Release.Namespace }} logs statefulset/{{ include "stalwart.fullname" . }} --all-containers --previous --tail=200

If the container fails with "operation not permitted", retain
NET_BIND_SERVICE: the official binary has a file capability for ports below
1024 and needs that capability in its bounding set.
