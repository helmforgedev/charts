# Secrets and External Secrets

NetBox requires a stable Django secret, database password, and Redis password.
An API-token pepper enables v2 API token hashing and is generated by this chart
by default. Changing the Django secret or pepper can invalidate application
security state. Production installations should use existing Secrets or
External Secrets rather than inline values.

When `externalSecrets.enabled=true`, each `items[]` entry renders an
`external-secrets.io/v1` ExternalSecret. Point `auth.existingSecret`,
`database.external.existingSecret`, and `cache.external.existingSecret` to the
target Secret names. Set `database.external.existingSecretPasswordKey` and
`cache.external.existingSecretPasswordKey` to the actual keys in those
Secrets; the bundled subcharts use `user-password` and `redis-password`,
respectively. The chart never reads values from the external provider.

Bootstrap credentials are separate so they can be removed or rotated after
the first administrator is created. Set `auth.superuser.enabled=false` after
initial provisioning.
