3. Readiness
============

  kubectl -n {{ .Release.Namespace }} rollout status deployment/{{ include "chiefonboarding.fullname" . }} --timeout=300s
  kubectl -n {{ .Release.Namespace }} get pods,service -l app.kubernetes.io/instance={{ .Release.Name }}

The init container waits for PostgreSQL. The HTTP probes validate the actual
Gunicorn listener configured by chiefonboarding.port.

4. Initial configuration
========================

Create the first administrator through the setup flow, then configure onboarding
workflows and integrations in the application. Set chiefonboarding.baseUrl to
the public HTTPS URL before sending links to employees.

5. Secrets
==========

Use stable existing Secrets for the Django secret key, database password, and
integration credentials. The generated application Secret is retained across
upgrades and uninstall; back it up and delete it only when retiring the release.
{{- if or .Values.chiefonboarding.existingSecret .Values.database.external.existingSecret .Values.postgresql.auth.existingSecret }}

After rotating an externally managed Secret, restart the application because
Helm cannot checksum external Secret data:

  kubectl -n {{ .Release.Namespace }} rollout restart deployment/{{ include "chiefonboarding.fullname" . }}
  kubectl -n {{ .Release.Namespace }} rollout status deployment/{{ include "chiefonboarding.fullname" . }} --timeout=300s
{{- end }}

6. Backup and upgrade
=====================

Back up PostgreSQL and the retained application Secret together. Test restore
before upgrades, read upstream release notes, and verify migrations plus a
representative onboarding workflow after rollout.

7. Troubleshooting
==================

  kubectl -n {{ .Release.Namespace }} describe deployment/{{ include "chiefonboarding.fullname" . }}
  kubectl -n {{ .Release.Namespace }} logs deployment/{{ include "chiefonboarding.fullname" . }} -c wait-for-db --tail=100
  kubectl -n {{ .Release.Namespace }} logs deployment/{{ include "chiefonboarding.fullname" . }} -c chiefonboarding --tail=200
  kubectl -n {{ .Release.Namespace }} get events --sort-by=.lastTimestamp

Check database reachability, Secret keys, the configured base URL, NetworkPolicy
peers, and integration endpoints before restarting the pod.
