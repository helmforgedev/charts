1. Application overview:
   QuestDB is a high-performance time-series database designed for real-time analytics.
   This chart deploys an open-source standalone instance with support for PostgreSQL wire protocol,
   InfluxDB Line Protocol (ILP), REST/HTTP queries, and interactive Web Console.

2. Architecture:
   - Workload type: StatefulSet (single-instance standalone deployment)
   - Database Root: /var/lib/questdb (contains data, configuration, and WAL logs)
   - High Availability: Not available in OSS edition; persistent storage preserves data across restarts
   - Security Note: Keep service internal unless transport encryption is provided by an Ingress or Gateway

4. Credentials and authentication:
   Administrative username: {{ .Values.questdb.httpUser }}
   PostgreSQL wire protocol username: {{ .Values.questdb.pgUser }}
   Authentication secret: {{ include "questdb.authSecretName" . }}

   To retrieve the administrative HTTP password:
     kubectl get secret -n {{ .Release.Namespace }} {{ include "questdb.authSecretName" . }} -o jsonpath="{.data.{{ .Values.questdb.httpPasswordKey }}}" | base64 -d && echo

   To retrieve the PostgreSQL wire protocol password:
     kubectl get secret -n {{ .Release.Namespace }} {{ include "questdb.authSecretName" . }} -o jsonpath="{.data.{{ .Values.questdb.pgPasswordKey }}}" | base64 -d && echo

5. External Secrets integration:
{{- if .Values.externalSecrets.enabled }}
   ExternalSecrets is enabled for synchronizing credentials.

7. Operational guidelines and snapshots:
   - Backup / Storage Snapshots:
       Before taking a persistent volume snapshot, execute SQL command: CHECKPOINT CREATE;
       After the external volume snapshot finishes, execute: CHECKPOINT RELEASE;
   - Configuration:
       Custom properties can be supplied in .Values.questdb.serverConfig to tune memory and table storage.
